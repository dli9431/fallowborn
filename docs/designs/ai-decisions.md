AI decision authoring

Scope

Live campaign consumers use aiWarPolicy for consideration, strength margin, maximum offensive commitments and aggression appetite, with explicit government warChance overriding the policy. The legacy bellicose field retains its exact effect. New ordinary targets use aiExpansionPolicy with legal candidates and one batched regional fact projection; default aggression ascending/id tie order preserves the former selector without an RNG draw. Custom weighted choices draw once. Raids keep one uniform target draw by default; aiRaidTargetDevelopmentWeight in [0,100] optionally weights developed counties. aiRaidChance and breakawayChance now use the ordinary realm-scoped balance reader. Explicit zero raid chance is respected instead of falling through the former logical-or default. Ownership, legal checks and financial transactions remain canonical.

AI choices have separate candidate enumeration, canonical eligibility, pure facts, preference evaluation, selection and apply steps. Authorable preferences never supply legal permission, resources, ownership, technology, physical reach or combat power. Trusted engine modules retain those algorithms and transactions. The policy infrastructure described here exposes pure decision projections; existing live AI consumers keep their current code until individually converted. No additional scheduler, autonomous action or strategic planner is installed by loading this API.

Public policy contract

FBDATA.aiDecisionPolicies is a table keyed by stable lowercase snake_case id. Each complete record has family, mode, parameters, order, weights, bias, tieBreak and adjustments. Families are war, expansion, tactics, investment, research, intrigue, diplomacy, religion and government. The trusted engine defines each family's balance selection key, supported numeric facts and bounded parameter names. Definitions select first, ordered or weighted algorithms; JSON never registers algorithms, functions, expressions, state paths or recursive conditions. Adding a new fact or parameter requires an engine protocol extension and its documented real consumer.

Policy ids are selected through aiWarPolicy, aiExpansionPolicy, aiTacticsPolicy, aiInvestmentPolicy, aiResearchPolicy, aiIntriguePolicy, aiDiplomacyPolicy, aiReligionPolicy and aiGovernmentPolicy in balance. Selection uses the existing global, era, government-form, bookmark/revision, runtime-mod precedence through FB.balanceFor. Scalar parameters already owned by balance, agencyRules, traitMechanics or government strategyParameters keep those owners; do not add a duplicate setting here. A layer may omit a selection key. A declared unknown policy, wrong family or malformed policy is an error, never a fallback to another policy.

Parameters are complete bounded per-family records, listed by the trusted protocol. They describe preference inputs only; existing consumers have not yet adopted them. Order is at most sixteen unique supported fact/direction records, where direction is asc or desc. Ordered mode compares these lexicographically. Weights are supported-fact numeric coefficients between -100 and 100; weighted score is max(0, bias + sum(fact * coefficient)), with finite fact/score limits. First mode keeps eligible input order. tieBreak is input or id; weighted mode retains input order for cumulative sampling. First requires empty order/weights and zero bias; ordered requires nonempty order and empty weights/zero bias; weighted requires empty order and at least one weight or positive bias. Unsupported or unused fields reject.

Adjustments are at most thirty-two declared trait/aim selectors. Each has kind, id and multiply, naming supported parameter multipliers from zero through four. Validate ids against effective traits and agencyRules.aims, including same-import additions. Apply each matching selector once in declaration order, regardless of duplicate runtime trait ids; clamp and, for integer parameters, round once after combination. Do not infer a character or aim inside the generic evaluator. The owning caller supplies current trusted ruler inputs; character identity, succession and trait synchronization belong to their existing owners. No default adjustment activates trait behavior in an unconverted consumer.

Evaluation and choice

FB.aiDecisions.resolve(state, realmId, family) returns a detached compiled policy selected for the current campaign and government. FB.aiDecisions.report(policy, candidates, inputs) accepts at most 2048 unique-id candidates with explicit eligible boolean and a plain facts record of supported finite numeric facts. It returns detached parameter values, matched adjustments, per-candidate facts and score components, eligible ordering and total weight. Missing required facts reject, not zero-fill. Ineligible candidates never receive a selectable weight. Unknown input keys, malformed metrics and duplicate ids reject before choice. Reporting never reads campaign resources, RNG or uid and cannot authorize apply.

FB.aiDecisions.pick(report, roll) is pure. First/ordered return the leading eligible id. Weighted selection requires an explicit roll in [0,1), supplied by a canonical caller using FB.rng only when that legacy decision would have drawn; zero total or no eligible candidates returns null. The API never draws randomness itself, persists reports or issues orders. Keeping draw cadence, candidate order and rechecking current state is the consumer's responsibility. Stale reports are advisory and cannot replace canonical transaction validation.

Lifecycle and compatibility

World revisions can replace the whole balance field through the canonical revision resolver. An omitted revision balance inherits the root; an explicit empty table clears the root bookmark overrides for that revision. Its individual values still obey the ordinary global/era/government/bookmark/mod balance precedence. Retained-save readers select the stamped revision, so fresh revision tuning does not change the retained revision's policy selection. Validate every declared revision through the same balance and AI-reference rules.

Boot validates shared policy definitions and shared selection layers with catalogFaults(data,null,{worlds:false}); it does not resolve or validate unrelated world revisions. Normal import preparation uses the exhaustive default and inspects every declared bookmark/revision balance reference. Runtime world validation checks its own resolved balance through balanceLayers.problems. A broken reference in an unused world does not become a global mod-readiness error. Canonical revision shape and start failure isolation retain their existing owners.

Compile policies only when the effective definition table changes or an explicit invalidation occurs, never by scanning every policy for each candidate. Resolution reads current layered selection on every call; it must not cache a realm's trait, aim, campaign or form. Detached import preparation validates definitions and every declared selection in global balance, eras, government forms and all bookmark revisions without publishing or compiling against live state. Whole policy records replace by id; nested parameter maps and arrays do not merge. Null/deletion is unsupported; choose a valid disabled decision policy through supported zero parameters where the consumer permits it. Mod removal/replacement follows the existing ordered-stack/reload path and exact content fingerprints.

No new saved fields or save version are needed. Matching restore recomposes from the stamped campaign revision and matching mod stack; existing wars, routes, offers and resources remain unchanged. Default records are dormant in live decision paths, so simply loading them must not consume RNG or alter decisions. Technology impact: none for this internal policy projection/refactor; it creates no independently gateable action or gameplay eligibility. New consumer capability would require its own review.
