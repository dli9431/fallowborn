Schema-3 execution has exactly revision, lastTurn, paused, orders, lastCommitTurn and campaignId. Its ordinary actor, host, command generation and issued turn provenance remain mandatory. This adapter retains cursor zero, including after completion. Detached restore accepts a truthful stale campaign ticket for subsequent live reconciliation, but never upgrades, orders, rejoins, repairs or completes it. Missing fields, foreign campaign bindings, future action days, unsupported modes and schema downgrades are rejected. Ordinary exact mod fingerprints include the adapter and its finite windows.

Declarations

A program has exactly schema, id, commandId and steps. schema is 1; id is a lowercase identifier of at most 96 characters; commandId equals the same mobile.command.id. Authored opening principals and a command are required. There are 1-16 ordered steps. Each step has exactly id, after, window, columnId, adapter, terms and requirements. Step ids share the program identifier bound and are unique within their owning realm and program. after is a distinct list of earlier step ids, at most 16; only completed predecessors satisfy it. Empty dependencies permit concurrent reviews on separate columns. Forward references and cycles are rejected.

window has exactly startTurn and endTurn, integer absolute campaign days with 0 <= startTurn < endTurn <= 1440. Start is inclusive and end exclusive. Windows express opportunities without asserting a battle date or result. columnId must select an actual declared slot when columns are present; it must be null for a single-host command. A retired or missing selected host does not fall back to another column.

requirements has exactly minMen, minFood, minTreasury, memberIds and access. minMen is an integer from 0 to 100000000, minFood a finite number from 0 to 1000000000 and minTreasury a finite number from 0 to 1000000. Thresholds read only that actual host's men and carried food and the existing public treasury. Camp food and private gold cannot satisfy them. memberIds contains at most 32 distinct authored principal member ids; every listed member must currently retain allegiance and a living available principal. access has exactly mode (field or camp) and countyIds, up to 16 distinct inhabited physical county ids. Each must pass current canonical passage for the selected mode, including the ordinary hostile-field rules. Requiring access supplies no agreement or procurement entitlement.

Supported adapters

wait has empty terms and observes waiting. It still requires the real host, command, consent, resources and window. A successful program commit records that review once without issuing an order or transferring resources. Set startTurn to the earliest eligible review day; no fixed-date event or battle is implied.

route terms have exactly mode and waypoints. mode is field or camp; waypoints is an ordered list of 1-16 real inhabited physical county ids. Repeated counties are permitted for a return route. The saved cursor selects one waypoint. A halted host already at that waypoint reports reached without advancing the cursor. A camp observation additionally requires the actual civilian camp there. Otherwise field delegates march and camp delegates move to the current canonical review. The army owner computes real adjacency, route and access. Manual movement, a broken host or an interrupted commitment refuses a new program review. No waypoint relocates people or changes permanent household residence.

supply terms have exactly action: trade or recruit, plus load or unload only for column commands. The selected profile must have supplyPolicy. Existing pure policy planners choose the exact current bounded terms and existing canonical reviews determine affordability, stock, locality, capacity, ordinary unit eligibility and pledged population. There is no authored arbitrary purchase amount or replacement entitlement. A missing or refused policy operation stays unavailable.

war terms have exactly causes, a one-entry array containing exactly type, enemy and target. The only currently supported mobile objective type is aggression. enemy references another declared realm and target an inhabited physical county. The canonical war declaration review alone decides current eligibility, consent, frontier, control, prior commitments and actual war creation. A declaration or successful review promises neither conquest nor battle. Other territorial claim packages are outside this adapter's supported boundary.

access_offer terms have exactly partnerRealmId, countyIds, capacity, allowRecruit, price and duration. The partner is another declared realm; countyIds is 1-16 distinct inhabited counties; capacity is an integer 1-100000000; allowRecruit is boolean; price is an integer 0-1000000; duration is an integer 1-1440. The shared mobile offer owner reviews current counterpart control, available capacity and member consent. Offering does not accept on the partner's behalf, pay, protect a person or grant passage. Acceptance remains the separate exact outside actor's canonical transaction. Realm targets resolve through the ordinary start-adoption alias at review, while declarations and saved definition identities remain unchanged.

Dispatch and progress

An operation-backed route commit records one bounded ticket for the selected actual host and current waypoint, actor, mode, war reference and command generations. It advances no cursor and moves no person directly. Only a later halted observation at the actual waypoint advances one cursor; camp routes also require the civilian camp there. Repeated waypoints still require distinct current commits. Completion means the last actual waypoint was observed. Supply completes once after the exact policy transaction succeeds, war after actual canonical declaration, and access_offer after an offer is recorded. These statuses do not assert replenishment forever, victory, conquest, acceptance or protection.

day(state) reconciles only active program records, then dispatches at most one successful step per column or single host per campaign turn in declaration order. Unavailable steps wait or refuse, and independent columns may proceed. A live player leader withholds automatic execution for the whole command; a player column commander withholds it for that column. Manual movement and hold flags refuse program dispatch. The mobile daily hook reconciles before normal mobile maintenance, consumes normal food, then invokes program dispatch before ordinary army movement. Legacy seasonal mobile AI and automatic policy procurement/recovery are withheld whenever a program marker exists, including terminal programs. Provisioning from actual camp stock, consumption, market production, combat and ordinary movement retain their existing owners. Explicit supply steps and manual operations remain available.

Every owned march is rechecked before movement against its current command, exact actor/column, required living members, men, carried food, public treasury, declared access, actual remaining path and war reference. A lost requirement stops only a still-matching program route without changing position or crediting arrival. Expired windows mark pending steps expired, remove their route tickets and never force a battle, peace or historical withdrawal. Command replacement, changed war or a replacement/manual route pauses intent. Retreat and replacement routes with different goals remain under the army owner. Missing or retired hosts never select a substitute or regenerate a column. No per-tick whole-state clone is used; work is bounded by sixteen steps and at most four tickets per command.

Control and manual ownership

reviewControl(state, request) returns the canonical governmentSelection envelope for source expedition_program. request has exactly realmId, action, stepId and actor. actor is the exact living current overall character leader under a valid mandate. action is pause, resume, cancel or redirect. stepId is null except for redirect, where it names a pending declared route step with satisfied predecessors and a current eligible window, host, resources and route. Apply through mobile.commit or governmentSelection.commitSource. Full control review and canonical terms are rechecked at commit. These controls have no monetary cost or resource reward and are available through the shared source API; no new screen is introduced.

Pause halts and clears only matching owned routes, retaining pending checkpoints. Resume permits fresh reviews. Cancel halts matching owned routes, cancels pending steps and makes the program terminal. Redirect purely previews the selected declared alternative after halting owned orders on a detached candidate, then stops those orders, cancels competing pending steps on the same column and resumes intent. Its destination is still dispatched through a new canonical route review. It cannot invent a destination or waive dependencies. A withdrawal is an independently eligible declared return route, with the same physical movement, supplies and passage rules. Authors should omit an alternative's dependency on the path it replaces; cancelled predecessors never count as completed. Other columns retain their checkpoints and can resume their own reviews.

Successful manual mobile/column/command transactions pause the program through the common source-commit boundary, preserving the newly committed manual host order. Raw single-host orders also pause it. Failed transactions do not pause it. Outside acceptance and personal pledge, departure or admission remain independent facts, rechecked by the program rather than mistaken for commander instructions. Only the synchronous internal dispatch permit suppresses this manual-order observation. A halted or replaced program never overwrites a later manual order. Program control does not cancel an ordinary war or dissolve a following.

Persistence

An opted-in schema-3 mobile row owns expeditionProgram with exactly schema, id, commandId, definitionKey, status and steps. schema is 1; ids match the exact declaration; definitionKey is its exact JSON representation. status is active, cancelled or complete. steps retains the declaration's exact length and order, each with exactly id, status and cursor. Step status is pending, complete, cancelled or expired. A route cursor is an integer waypoint index while unfinished and equals the waypoint count only when complete. Every other cursor is zero. Progress and completion require all predecessors complete. A complete program has no pending step. Cancelled history may retain its unfinished checkpoints.

Initialization preflights the full fresh batch before invoking the existing owners, then creates only initial active/pending/zero schema-1 checkpoints. It never resets an existing row. The first live dispatch, reconciliation change, manual pause or control commit upgrades that marker to schema 2, adding exactly execution. execution has revision (integer 0-1000000000), lastTurn (integer -1 to 1440, no later than the campaign turn), paused (boolean) and orders (at most four distinct host/step tickets). Each ticket has exactly stepId, hostId, countyId, mode, actorId, commandRevision, leaderGeneration, warId and issuedTurn. The step must be pending route intent at the current declared waypoint and mode. Host identity must match its canonical declared slot or migration host, actor must exist, command generations cannot be future, and issuedTurn is an integer 0-1439 no later than the campaign turn. warId is null or a bounded ordinary-war reference string. Actual live host loss or mandate expiry does not invalidate historical ticket identity on restore; reconciliation subsequently handles it without replay. Paused and terminal records have no tickets.

Missing opted-in records, undeclared markers, forged definitions, extra fields, reordered identities, invalid cursors, duplicate hosts/tickets and impossible predecessor completion are rejected on detached restore without repair. Matching restore retains schema 1 or 2 exactly, including paused, in-flight, completed, cancelled and expired history, without dispatch, upgrade, reinitialization or advancement. Existing worlds omit the optional field and retain their prior schemas. The existing schema-3 mobile owner and save envelope are unchanged.
