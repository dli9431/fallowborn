Expedition program declarations and reviews

The optional mobile.expeditionProgram schema 1 describes bounded intent over an existing command and its real single host or declared columns. It creates no host, troops, household carriage, residence, account, authority, stock or war. Its current consumer validates declarations, initializes identity checkpoints once and projects pure current reviews. There is no daily dispatcher, automatic progression, cancellation transaction or invasion simulation in this contract.

Ownership and technology

js/expedition_programs.js loads immediately after js/mobile_columns.js. Trusted private adapters delegate to mobile.review, reviewColumns, supplyReview and columnSupplyReview. Ordinary JSON can select supported adapters and typed terms, never register code or saved-state writes. The existing mobile declaration and authority save validators compose this owner. No new mod root, story type or save envelope is introduced.

The expedition_program_reviews technology impact decision is none. Planning and observing existing authority, living consent and resources have no credible research prerequisite. Every canonical operation retains its ordinary unit, transport, equipment, access and war gates. Ordinary manual operations remain available without a program.

Declarations

A program has exactly schema, id, commandId and steps. schema is 1; id is a lowercase identifier of at most 96 characters; commandId equals the same mobile.command.id. Authored opening principals and a command are required. There are 1-16 ordered steps. Each step has exactly id, after, window, columnId, adapter, terms and requirements. Step ids share the program identifier bound and are unique within their owning realm and program. after is a distinct list of earlier step ids, at most 16; only completed predecessors satisfy it. Empty dependencies permit concurrent reviews on separate columns. Forward references and cycles are rejected.

window has exactly startTurn and endTurn, integer absolute campaign days with 0 <= startTurn < endTurn <= 1440. Start is inclusive and end exclusive. Windows express opportunities without asserting a battle date or result. columnId must select an actual declared slot when columns are present; it must be null for a single-host command. A retired or missing selected host does not fall back to another column.

requirements has exactly minMen, minFood, minTreasury, memberIds and access. minMen is an integer from 0 to 100000000, minFood a finite number from 0 to 1000000000 and minTreasury a finite number from 0 to 1000000. Thresholds read only that actual host's men and carried food and the existing public treasury. Camp food and private gold cannot satisfy them. memberIds contains at most 32 distinct authored principal member ids; every listed member must currently retain allegiance and a living available principal. access has exactly mode (field or camp) and countyIds, up to 16 distinct inhabited physical county ids. Each must pass current canonical passage for the selected mode, including the ordinary hostile-field rules. Requiring access supplies no agreement or procurement entitlement.

Supported adapters

wait has empty terms and observes waiting. It still requires the real host, command, consent, resources and window. It issues no order and supplies no completion receipt.

route terms have exactly mode and waypoints. mode is field or camp; waypoints is an ordered list of 1-16 real inhabited physical county ids. Repeated counties are permitted for a return route. The saved cursor selects one waypoint. A halted host already at that waypoint reports reached without advancing the cursor. A camp observation additionally requires the actual civilian camp there. Otherwise field delegates march and camp delegates move to the current canonical review. The army owner computes real adjacency, route and access. Manual movement, a broken host or an interrupted commitment refuses a new program review. No waypoint relocates people or changes permanent household residence.

supply terms have exactly action: trade or recruit, plus load or unload only for column commands. The selected profile must have supplyPolicy. Existing pure policy planners choose the exact current bounded terms and existing canonical reviews determine affordability, stock, locality, capacity, ordinary unit eligibility and pledged population. There is no authored arbitrary purchase amount or replacement entitlement. A missing or refused policy operation stays unavailable.

war terms have exactly causes, a one-entry array containing exactly type, enemy and target. The only currently supported mobile objective type is aggression. enemy references another declared realm and target an inhabited physical county. The canonical war declaration review alone decides current eligibility, consent, frontier, control, prior commitments and actual war creation. A declaration or successful review promises neither conquest nor battle. Other territorial claim packages are outside this adapter's supported boundary.

access_offer terms have exactly partnerRealmId, countyIds, capacity, allowRecruit, price and duration. The partner is another declared realm; countyIds is 1-16 distinct inhabited counties; capacity is an integer 1-100000000; allowRecruit is boolean; price is an integer 0-1000000; duration is an integer 1-1440. The shared mobile offer owner reviews current counterpart control, available capacity and member consent. Offering does not accept on the partner's behalf, pay, protect a person or grant passage. Acceptance remains the separate exact outside actor's canonical transaction. Realm targets resolve through the ordinary start-adoption alias at review, while declarations and saved definition identities remain unchanged.

Pure review boundary

FB.expeditionPrograms.adapterIds() exposes the bounded trusted adapter names. definitionFaults(declaration, provinces, realms, profiles) is detached and participates in whole-bookmark and ordinary Mods validation. FB.expeditionPrograms.review(state, realmId, stepId, actor) accepts an optional exact character actor, defaulting to the current command leader. A column actor must have that column's current scope; canonical operations retain any stricter overall-leader requirement. It returns allowed, reason, observation, operation, facts and signature alongside realmId, stepId and resolved actor. operation is either null or the existing canonical source/request/review envelope. No rendered prose is saved.

facts distinguish hostId, columnId, fieldCountyId, campCountyId, men, fieldFood, campFood, treasury and cursor. These locations do not assert an accompanying household, permanent residence, safe passage or battle evidence. Review changes neither program state nor canonical resources, orders, RNG, identities or registries. Closed, early, expired, dependency-blocked, invalid-command, missing-host, unavailable-member, insufficient-resource, inaccessible and manually committed states are refused without repair or lifecycle changes.

matchesReview(state, review) recomputes the complete projection, including current program, command, member/agreement state, actual host, camp, public money, declared access ownership and canonical terms. A changed review cannot authorize an old action. This is a pure predicate, not a commit API. A future dispatcher must revalidate this entire program review immediately before the canonical commit and advance only a supported observation or successful transaction. Committing a naked canonical operation cannot establish program progress. Daily program execution, manual-intent ownership, redirect/withdraw decisions and cancellation/progress transactions remain outside this declaration/review contract.

Persistence

An opted-in schema-3 mobile row owns expeditionProgram with exactly schema, id, commandId, definitionKey, status and steps. schema is 1; ids match the exact declaration; definitionKey is its exact JSON representation. status is active, cancelled or complete. steps retains the declaration's exact length and order, each with exactly id, status and cursor. Step status is pending, complete, cancelled or expired. A route cursor is an integer waypoint index while unfinished and equals the waypoint count only when complete. Every other cursor is zero. Progress and completion require all predecessors complete. A complete program has no pending step. Cancelled history may retain its unfinished checkpoints.

Initialization preflights the full fresh batch before invoking the existing owners, then creates only initial active/pending/zero checkpoints. It never resets an existing row. Missing opted-in records, undeclared markers, forged definitions, extra fields, reordered identities, invalid cursors and impossible predecessor completion are rejected on detached restore without repair. Matching restore retains completed, cancelled and expired history without replay, reinitialization or advancement. Live command loss, window expiry and control changes suspend current reviews without rewriting historical saves. Existing worlds omit the optional field and retain their prior schemas.
