Guarded original following parties

An optional mobile.guardedParty schema 1 binds the opening leader and up to fifteen other existing direct opening actors to an inhabited county and optional curated site, separately from civilian camp and field hosts. It names id, kind (protective_guard), location (countyId and optional siteId), hostRealmId, hostActorId, actorIds, duration (1 to 1440 days) and release (host_review). The leader must appear once; other principals cannot belong to the personal party. Every named actor has that declared home. The host actor must reference the current nonmobile hosting ruler; the host must actually hold the locality under its lawful sovereign. A landedCommandLink cannot also select this opening. No historical person, kinship, criminal accusation, population, food or protection guarantee is supplied.

Fresh batch preflight resolves all people and the host without mutation, checks ordinary custody and actual location and rejects overlapping parties before initialization. The existing following installs its one original leader with a suspended effective command. A schema-1 guardedParty record on that same mobile owner stores exact declaration provenance, original character ids, host identity/generation, start/end turns, status, change turn and revision. Guarded people never enter migration courtIds, including after release; moving a camp does not carry the personal party. Existing character residence and ordinary travel remain their location owners after release.

Guard status is guarded, expired, interrupted or released. Expiry does not release anyone or grant command. Death of the original leader, unavailable/replaced host, changed lawful holder or a closed following interrupts an unreleased record at the next mobile boundary. Pure projections withhold command and travel immediately. An expired record can still be released by its unchanged original hosting ruler. Interrupted authority is unresolved and cannot silently renew; a future transfer contract would be needed. Death of a companion never creates a replacement. Ordinary criminal/war custody is neither cleared nor absorbed by this protective arrangement.

FB.mobile.reviewGuard and the common FB.mobile.commit use the registered mobile_guard selection source. A release requires the actual original living hosting ruler, the same generation, lawful local control, personal presence at the guard county, an available original leader and an unreleased, uninterrupted record. The review binds exact party, issuer, locations, custody, turn and current state. Confirmation rechecks everything and releases only this protective restriction, costs zero and moves nobody. It creates no money, mandate, safe passage or family carriage. Player and AI callers use the same review and transaction; no automatic policy guesses the outside ruler's consent.

Following release, an original party member's command still requires actual presence at the current civilian camp without personal travel or an outstanding named journey. Reaching the camp uses ordinary travel and its normal price, route and eligibility; a county/site guard does not create a free journey. Personal party membership remains provenance, not an accompanied-travel contract. No automatic camp reunion or remote command is inferred.

Restore strictly checks the optional exact declaration, original actor identities, immutable locality, host generation and finite clocks. Released records have one release revision and a valid release turn; expired/interrupted records retain their original ids. Current political divergence is allowed without repairing history. Restore never initializes, releases, relocates, chooses a successor or replenishes stock. A missing record on an opted-in initialized following, a forged record on an ordinary following and migration carriage of any original party member reject. Omitted guardedParty retains all earlier declarations and saves unchanged.

Technology decisions: mobile_protective_guard is none because current people, lawful hosting and reviewed release are baseline personal and political relationships. mobile_separate_personal_party is independently none because identity and actual presence require no discovery. Ordinary military and travel technology rules remain binding.

The mobile command sheet uses existing fact/action cards and confirmation history to show party, actual locality, host, status, term and the zero-cost release review. It explains that release moves nobody and does not restore remote command. Back, Escape, Continue, scroll, disclosures and focus use the shared mobile flow. Literal FB.T chrome contains no saved rendered prose. The independent guarded-following-harbor.json and guarded-following-dune.json imports vary host, locality, companions and duration through the ordinary Mods path.
