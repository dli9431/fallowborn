Construction profiles

buildingProfiles author optional construction variants of an existing physical building. The base building id, role, settlement slot, county and demesne limits, shared construction group, geographic flags and repeat-price count remain canonical. A profile replaces only named supported numeric fields; omitted fields inherit the base value. Numbers are never added to their base counterparts. Bundled profiles are initially empty. Existing unprofiled assets keep their exact defaults and receive no profile on boot or restore.

Authoring

Each profile declares buildingId, name, desc, replace and requiresTech. Optional applicability intersects the base construction window and scope. Optional siteResourceProfile requires current lawful available capacity of that declared resource profile at the exact physical site; this is construction suitability, not an allocation, manufactured stock or operating receipt. Optional operationProfile and institutionProfile use the existing water-service and foundation owners, including exact assignments, prospective funding, office continuity and footprint occupancy. Imported code, callbacks, arbitrary overrides, role changes, extra capacity and executable predicates are rejected. Optional machinery requirements additionally name techImpactReview with an existing exact hard or soft decision. Base technology requirements are retained.

The supported replacement numbers are cost, upkeep, devMin, tax, dev, pop, prestige, piety, research, levy, retinue, archers, defense, siege, populationCapacity, populationFamineProtection, populationCrisisProtection, migrationAttraction and communityFaithPressure. Each is finite, nonnegative and at most 1000000. Existing operation validators additionally prohibit unsupported simultaneous awards or effect channels on water-bound facilities. These are typed simulation values, not historical yields.

Selection and payment

FB.buildingProfiles.definition composes one detached effective definition. assetDefinition reads the optional identity on a real asset. ids returns a stable sorted list of alternatives for one base. status returns the current construction-only profile blocker. quote takes countyId, settlement, buildingId, profileId and the explicit realm or character actor. An optional targetLevel is allowed only for a strategic fort. commit recomputes the exact quote before using ordinary player, baron or public construction. Direct canonical construction APIs also accept the optional profile argument and enforce the same eligibility. Selected construction spends from the real original payer, protects normal public/baron reserves and keeps one record under the base id. Repeated or stale confirmation pays nothing. A source claim, incumbent, date, holder, actor, price, purse, mod signature or competing local record change requires another review. Construction awards use replacement values exactly once.

Strategic fort profiles accept an empty replace object only: canonical four-level prices, duration, works, upkeep and military values stay in the fort owner. No operation or institution binding can be added to a strategic fort. Explicit player selection uses the ordinary sequential project transaction; pending projects retain their original profile through completion after the new-construction window expires. A profiled fort cannot switch profile on a later project. Public AI forts continue through the existing annual work-budget planner and its profile-aware startFortProject options, rather than the generic treasury-purchase adapter. The profile picker does not invent public fort funding.

Saved identity

New selected assets carry buildingProfile with exactly v:1, id and definition. definition is the canonical SHA-256 fingerprint of the complete profile and base declaration. It is not a copy of rendered text or a current operating projection. Required ordinary waterOperation and institutionBinding identities must also exist. Save validation rejects unknown, mismatched, extra-field and unsupported-version markers before adoption; absent old markers remain absent. Water receipts for profiled assets carry the same optional exact buildingProfile provenance so their original price remains checkable even after physical removal. Old unprofiled water receipts retain their original shape and interpretation. There is no new envelope or resource ledger, automatic resource grant, payment, effect or identity assignment on restore.

Presentation and boundaries

Building Works offers construction profiles grouped by their owning base building. Native full-width profile and exact-site selectors show replacement effects, maintenance, the real price, exact required technologies and the first blocker. A separate confirmation names the actual site and immediate private-purse expense. Back, Cancel, Escape and browser Back use the existing retained modal history, preserving selectors, source disclosures, scroll and focus. The technology sheet discovers actual profile consumers, rather than invented building ids. Profile name and desc use buildingProfile structured display owners; literal supplemental tables buildingProfiles_<suffix> are extracted statically without executing composers. Ordinary JSON names have English fallback.

The independent building-profiles-river.json and building-profiles-hill.json files import complete fictional worlds through Mods. River works contrast a modest default-like option with paid water service and an actual institutional foundation; hill works contrast a lawful grazing-site option with a dearer technology-dependent learned workshop. Their prices, site requirements, technologies, upkeep and replacement awards differ. Neither installs bundled historical assets or supplies.

This owner covers authoring, selection, new construction, pending construction identity and strict optional markers. Inherited profile placements, inherited operating policy, automatic alternative scoring and the complete fiscal, population, repair and AI consumer audit remain separate extensions. The shared operation projection already reads the selected definition, but this is not a claim that all existing count-based fiscal or repair readers have been converted. Existing default-only worlds remain unchanged. No shipped profile catalogue is enabled before those consumers are complete.

Technology decision

building_profile_selection is none: a choice of a typed construction definition is authoring and accounting, with no credible research dependency. Independently gated machinery must declare its own hard or soft review and real baseline fallback. The generic authoring capability introduces no machinery or national research reward.
